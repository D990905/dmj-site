## B. AWA · 자세 계열 (2026-09-01 논의)

옥대표: "AWA 는 실제 어택앵글을 결정한다고 봐야해서 보드 대비 스트럿의
상대적 각도를 추정하거나 비교해볼 수 있을거고, 나중에 실시간 코칭할때
실제 붐의 각도랑 보드의 정렬상태를 감지해서 당겨라 열어라 할 수 있지 않을까"

관계식: **AoA = AWA − (붐이 보드 중심선에서 벌어진 각)**

| | 항목 | 필요한 것 | 메모 |
|---|---|---|---|
| B1 | ✅ §498 — **원안 폐기, 재정의해서 구현** | — | 원안("AWA별 속도 곡선")은 **순환**이었다. AWA 는 속도로부터 계산되므로 CWA 를 고정하면 동어반복 — 실측 r = **−0.96 ~ −0.99**(전체 상관은 0.222 로 낮아 보여서 순진하게 만들면 그럴듯한 가짜 차트가 나온다). 대신 **"속도가 변하면 붐을 얼마나 더 당겨야 하나"**(ΔAWA = Δ붐각)로 바꿔 구현. 자세 탭 상단, IMU 없어도 나옴. **발견: 풍하 트림 요구량이 풍상의 3.5배**(같은 속도폭 기준), 그리고 **풍상 요구량은 풍속에 거의 둔감**(TWS 8~20kt 에서 편차 3° 이내). selftest 19/19 |
| B1b | 🔴 **부수 발견 — §494 AWS·AWA 가 v2 에서 한 번도 렌더된 적이 없었다** | — | `analyzeSession` 호출부 **5곳 전부**가 풍속을 안 넘기고 있었다(windConfidence 만). `hasTws` 가 항상 false → AWA·AWS 계산 자체가 안 됨. **§482(포일 바꿔도 예측이 안 변하던 것)와 같은 종류** — 기능은 다 있었고 입력만 끊겨 있었다. §498 에서 `analysisOpts()` 헬퍼로 배선. 추가로 **풍속 입력에 이벤트 핸들러가 아예 없어서** 값을 바꿔도 아무 일이 안 일어났다 — change/blur 배선 |
| B2 | **목표 붐각 절대값** (열린 루프) | 윙 양력곡선 기울기·영양력각 | §498 이 **변화량**은 냈다. 절대값은 윙의 양력곡선을 몰라 못 낸다 — 그것만 남았다 |
| B3 | **자세 해 + 리웨이** | RaceBox 자이로·가속 (이미 있음) | ⚠ **GyroZ 를 그대로 쓰면 안 된다** — 8/30 세션 실측 상관 r=−0.36. 30~40° 힐에서 센서 Z축이 지구 수직이 아니다. 자세 먼저 → 자이로를 지구 좌표로 회전 → 요 적분 → 직진 구간에서 COG 로 드리프트 보정. 그러면 `보드방향 − COG = 리웨이` |
| B4 | **AWA 를 보드 기준으로 정정** | B3 | 지금 AWA 는 **항적(COG) 기준**이다. 보드는 항적보다 리웨이만큼 높이 향한다(포일 2~5°) — 하필 트림 신호와 같은 크기라 그냥 두면 3~5° 틀린다 |
| B5 | **IMU 축 자동판정** | B3 와 같은 계산 | 옥대표: "센서를 어디에 붙여도 움직임을 보면 앞뒤위아래를 알 수 있지 않아?" → 맞다. ①가속도 평균 = 중력 → 아래 ②GPS 속도 미분과 상관 최대 = 앞 ③남은 축 = 좌우, 부호는 선회 원심가속도로. 확신도 낮으면 자동 판정하지 말고 그렇다고 말할 것 |
| B6 | **붐 센서 → 닫힌 루프 실시간 코칭** | 붐/핸들에 소형 IMU | 이게 있어야 "6° 과하게 당겼다" 를 감지한다. 그 전까지는 열린 루프뿐. **⚠ 이미 다른 프로젝트에 사양이 있다** — 세일링 코칭시스템 `03_SailTechMOTION/Boom_IMU_Spec_2026-08-25.md` (BNO085 9축 · ESP32 BLE · 벨크로 새들 · 3초 영점 · 카본붐 BLE 감쇠 → 안테나 외부). §498 의 열린 루프가 그 센서를 만나면 닫힌다 |
