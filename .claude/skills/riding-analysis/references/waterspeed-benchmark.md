# Waterspeed 앱 벤치마킹 (2026-09-03)

옥대표 제공 스크린샷 36장(`세일링 코칭시스템 개발/Water Speed/`) 전수 검토.
세션: Windfoil, 2026-09-03 부산 송정, 2:27:48 / 41.07km / 14kt N.

우리가 이미 이 앱의 **GPX·CSV 를 파싱해서 쓰고 있다**(옥대표 주력 기록 도구).
즉 경쟁이 아니라 **같은 데이터로 무엇을 더 보여줄 수 있느냐**의 문제다.

---

## 요약 — 세 줄

1. **가져올 것 딱 두 개가 압도적이다**: `수동 매뉴버 보정`(W1)과
   `풍속 자동 다운로드`(W2). 특히 W2 는 **D1·D4·E1 을 한 번에 푼다** —
   풍속계를 사지 않아도 된다.
2. 나머지는 대부분 우리가 이미 있거나(장비·택바이어스·폴라) 더 낫다.
   레그/런 스테퍼(W3)와 런별 타깃 대비(W4)는 **엔진이 이미 있고 배선만 없다** —
   §482·§494·§511·§514 와 같은 계열.
3. 이 앱의 약점은 **검증 없는 자동 산출**이다. 풍하 최적각 173°(포일에서
   물리적으로 말이 안 됨), 폴라 원시 노이즈, 단위 버그(거리 칸에 km/h),
   지도에 자이브 핀 57개. 우리가 세워 온 규칙(근거 없으면 안 그린다)이
   그대로 우위다.

## A. 가져올 것 (우선순위)

### W1 ⭐⭐⭐ 수동 매뉴버 보정 (Edit maneuvers)
지도의 매뉴버를 **하나씩** 고친다:
- Tack ↔ Jibe 재분류 토글
- START / END 를 **샘플 인덱스 단위**로 ‹‹ ‹ › ›› 조정 (#4346 → #4350,
  "5 points · 4s" 로 결과를 즉시 보여줌)
- Delete(오검출 제거) · + Add maneuver(누락 추가) · **Reset to auto**
- 하단: "6 Tacks · 57 Jibes — Tap a maneuver pill to edit it" · Save/Cancel

**왜 우리 V12 보다 낫나**: 우리 백로그 V12 는 '검출 임계값 슬라이더'였다.
그런데 검출 실패는 **전역이 아니라 개별**이다. 임계값을 내리면 잡히던 것까지
깨진다. 개별 보정이 옳은 축이다.
**우리가 더 낫게 할 것**: 고친 것을 `manual: true` 로 표시하고 자동값과
구분해 보관(§520 backfilled 와 같은 원칙). 되돌리기 가능. 그리고 **왜
자동이 틀렸는지**(회전각 미달·최저속 미달 등)를 pill 에 적어 주면 다음
세션에서 임계값을 조정할 근거가 된다 — 그들은 이유를 안 알려 준다.

### W2 ⭐⭐⭐ 풍속·풍향 자동 다운로드 (Download Wind Data)
세션 Edit 화면 하단에 `Download Wind Data` 링크. 시각·위치로 기상
데이터를 끌어와 Wind speed(kn)·Wind direction 을 채운다.

**이게 D1·D4·E1 을 푼다.** 백로그에 "계기 풍속 3~4개면 닫힌다"고
적어 둔 그 열쇠다. 지금은 옥대표 눈대중(±4~5kt)이라 속도-풍속 곡선
기울기를 맞출 근거가 없다.
**구현 경로**: Open-Meteo `archive-api` 는 **키 불필요 · CORS 허용 ·
과거 시간별 10m 풍속/풍향 무료**다. GitHub Pages 정적 호스팅에서
그대로 호출된다(웨어러블 OAuth 와 달리 서버가 필요 없다).
**우리가 더 낫게 할 것**: 그들은 값 하나를 채워 넣고 끝이다. 우리는
①세션 시간대에 걸친 **시간별 곡선**을 받아 구간별 풍속을 쓰고
②우리 `RDWindConfirm`(§505) 의 트랙 기반 추정치와 **대조**해서
어긋나면 그렇다고 말한다. 기상 모델은 해안에서 잘 틀린다 —
두 값을 나란히 놓는 것이 한 값을 단언하는 것보다 정직하다.

### W3 ⭐⭐ 레그/런 스테퍼 + 지도 하이라이트
`Legs ▾ | 1 / 20 | ‹ ›` 로 넘기면 **그 레그만 지도에 보라색으로** 뜨고,
카드에 Avg/Max Speed·VMG·TWA·Distance·Direction(upwind/downwind)·Duration.
`Runs ▾`(1/30) · `Tacks ▾`(5/6) 로 대상 전환.
카드 테두리 색이 upwind(초록)/downwind(분홍)로 갈린다.

우리 백로그 V9. `RDAnalysis.detectRuns` 는 이미 있고 §456 Gain/Loss 가
레그를 쓰고 있다 — **스테퍼 UI 만 없다.**
**우리가 더 낫게 할 것**: §515 궤적 겹치기와 붙이면, 레그를 넘길 때마다
그 레그의 궤적이 다른 레그들 위에 겹쳐 보인다. 그들에겐 없다.

### W4 ⭐⭐ 런별 "Performance vs Target"
런 카드 안에 별도 박스: `Target VMG 8.78 Kts · % of Target 96% ·
Delta 0.32 Kts` + **HIGH** 신뢰도 칩 + ⓘ.

우리는 `buildTargetPolar` · `computeTargetComparison` · `compareToTargetBand`
가 **이미 있는데**(§474) 런 단위로는 안 쓴다. 또 배선 결함 계열.
**우리가 더 낫게 할 것**: 그들의 타깃은 "이 세션 내 최고"라서 자기
자신과 비교하는 순환이다(96%가 잘한 건지 알 수 없다). 우리는 §474
타깃 밴드가 **풍속 버킷별 모집단**을 쓰므로 "같은 바람에서 평소의 나"
대비가 된다 — 그쪽이 답이 되는 비교다.

### W5 ⭐ 회전 손실을 **미터**로
Tacks 카드에 `Lost 15 m`. 우리는 손실을 %로만 준다(44%).
미터는 손에 잡힌다 — "이 자이브에서 15m 를 잃었다".
§456 Gain/Loss 가 ladder rung 으로 이미 거리를 다루므로 재료는 있다.

### W6 ⭐ 포일링 구간 구조
`Sections 13 · Longest Segment 19km · Longest Time 00:37:13 · Distance % 94%`.
우리는 activeTime/activeDistance/activeRatio 만 있고 **끊긴 횟수와
가장 긴 연속 구간**이 없다. "37분을 안 떨어지고 갔다" 는 실력 지표다.

### W7 진입/이탈 **VMG** 와 변화율
그들: `Entry Speed 16.8 → Exit 11.3 (−32.6%)`, `Entry VMG 13.9 → Exit 0.4 (−96.8%)`.
우리는 속도만. VMG 진입/이탈은 "빠르게 나왔지만 방향을 버렸다" 를 잡는다.

### W8 Remove Max Speed · Clone
- `Remove Max Speed`: GPS 스파이크 한 방을 원터치로 제거
- `Clone` / `Clone & Remove Spikes`: 원본을 두고 사본에서 편집
우리는 편집이 제자리라 "Restore full track" 뿐이다. Clone 이 있으면
**편집본과 원본을 나란히 비교**할 수 있다.

### W9 세션 메타 입력 (일부는 우리도 있음)
`Activity type`(For fun / …) = 우리 **V15** · `How did this activity feel?`
5단 표정 = 우리 **V7** · `Comment` = 우리 **V4** · `Equipment 1·2·3`
= 우리 **V2(§520 완료)** · Photo.
표정 5단은 §513 Hooper 4문항과 **겹치므로 하나로 합쳐야 한다** —
둘 다 물으면 같은 걸 두 번 묻는 셈이다.

### W10 위치 이름 · Farthest point from start
`From: 송정해변로, 부산광역시` (역지오코딩) · `Farthest point from start 1.84 km` ·
`Linear Distance 0.07 km`. 세션 자동 명명에 쓸 수 있다.

### W11 런별 `Angle Change ↑18.4°`
그 런 동안 풍각이 얼마나 변했는지 = 헤더/리프트 신호. 우리 §505 가
세션 전체 풍향을 다루지만 **런 단위 변화**는 없다.

### W12 거리 기반 베스트에 장거리 추가
그들: 2s/5s/10s/20s + 5Mi/10KM/10Mi. 우리: 100m/250m/500m/1NM/Alpha500.
장거리(5km·10km)는 지구력 축이라 우리 것과 겹치지 않는다.

## C. 베끼면 안 되는 것 (그들의 결함)

1. **풍하 최적각 173°** — 포일에서 데드다운윈드는 물리적으로 최적일 수
   없다. 노이즈 낀 VMG 의 argmax 를 그대로 출력한 것이다.
   우리 규칙(근거 없으면 안 그린다)이 이걸 막는다.
2. **폴라 원시 노이즈** — 스무딩·비닝 없이 raw 를 그려 톱니가 화면을
   덮는다. 우리는 7.5° 빈 + p95 를 쓴다.
3. **지도에 자이브 핀 57개** — 라벨이 서로 겹쳐 하나도 안 읽힌다.
   §515 에서 우리가 택한 길(모집단은 흐리게, 고른 것만 진하게)이 맞다.
4. **단위 버그** — `Longest Segment 0km/h`(거리 칸에 속도 단위),
   Foiling 카드가 `Total Time 00:00:00 · Sections 14` 를 동시에 표시.
   §485 에서 우리가 같은 종류를 고쳤다.
5. **이중 축 차트** — 속도(왼쪽)와 심박(오른쪽)을 한 그래프에.
6. **Best VMG 2.4 km/h** 가 Best Speed 40.1 km/h 옆에 — 업윈드 베스트
   VMG 가 2.4km/h 일 수 없다. 검산이 없다.
