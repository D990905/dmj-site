# 밴티지 세일링 앱 벤치마킹 (2026-09-01)

옥대표가 자기 세션 화면 10장을 보내 줌. 지표는 우리가 거의 다 갖고 있고
**차이는 배치와 맥락**이다. 아래는 가져올 것과 **가져오면 안 되는 것**.

---

## 🥇 가져올 것 (가치/비용 순)

### ① 포트/스타보드 분포를 **나란히** — 박스플롯 ↔ 바이올린 토글
Speed Analysis 화면이 Port·Starboard 박스를 좌우로 놓고 아래에
`SOG | VMG | CWA | TWA | Heel` 스위처를 둔다.

**우리에게 제일 큰 항목이다.** §420·§421이 통째로 P/S 비대칭 얘기였는데
우리는 **표로만** 보여준다(숫자 두 칸). 나란히 놓으면 비대칭이 한눈에 보이고,
"어느 택이 문제냐"가 설명 없이 읽힌다. 데이터는 이미 `tackSplit` 에 있다.

### ② 세션별 장비 + **트림** 기록
`Hull R73 / Mainfoil R6_430 / Mast R6_112 / Other R6_V2 / Wing FDS5.0`
+ Equipment | **Trim** 탭.

우리 RDGear 는 **폼 입력 한 벌**이라 세션에 안 붙는다. 그래서
 · D2(기하 기반 윙 추천)가 "그날 뭘 탔는지" 를 모른다
 · §482 포일 배선이 이력 비교로 못 이어진다
장비가 세션에 붙어야 "이 포일일 때가 빨랐다" 가 나온다.

### ③ `ALL | TOP 50% | TOP 20%` **전역 모드 스위치**
우리는 top50/top20 을 표의 **열**로 준다. 저쪽은 **모드**라서 분포·차트가
전부 같은 모집단으로 바뀌고, **지금 보는 게 어느 모집단인지 화면에 항상
떠 있다.** §474 에서 "모집단을 명시한다" 고 정한 것과 같은 방향.

### ④ 세션 제목을 문장으로 + 자유 메모
`12-17knots under-pull FDS 5.0` · `Enter notes here...`
한 줄에 **풍속 범위 · 본인 판정(under-pull=파워부족) · 장비**가 들어 있다.
우리는 파일명(`s.gpx`)만 띄운다. "under-pull" 은 **§487 문답이 캐내려는
바로 그 정보**이고 윙 추천의 입력이다 — 본인이 적어 주면 추정할 필요가 없다.

### ⑤ 회전 집계 헤드라인
`Avg Minimum Speed 10.2kts · Avg Maximum Heel 38.8° · Avg Turning Rate 23.5°/s`
우리는 **회전 하나하나로만** 보여준다. 세션 평균이 없다. 값은 이미 계산돼
있으니 표 위에 얹기만 하면 된다. **택 23.5°/s vs 자이브 16.1°/s** 처럼
택-자이브 대조가 바로 읽히는 게 좋다.

### ⑥ 전 지표 인라인 델타% (단, 아래 함정 3개를 피해서)
모든 숫자가 "평소 대비" 를 달고 다닌다. 우리는 델타가 PDF 와 §490 시즌
흐름에만 있고 **본 화면 통계표에는 없다.** 이력은 이미 있으니 배선 문제.

### ⑦ 별점 "How was your session?" → **체감 vs 실측 갭**
별 하나만 보면 약하다(원인을 모른다). 우리 SPS 와 짝지으면 새 축이 생긴다 —
**3점을 줬는데 SPS 가 88이면 그 격차가 신호다.** §487 이 물어볼 거리를 얻는다.

### ⑧ Wind Strength 등급 밴드
`True Wind 104°` 옆에 `Wind Strength: Medium`. 우리는 숫자만 준다.
**세일테코에 바람 5등급 분류가 이미 있다**(`10_Reference/wind_classification/`)
— 새로 정할 게 아니라 있는 걸 쓴다.

### ⑨ 번호 매긴 런(레그) 목록
`1 | 11.8km | 17.2kts | 22min`, Upwind|Downwind|Custom 탭.
택에서 택까지가 단위다. 우리는 `run` 이 내부 설정에만 있고 화면에 없다.
§456 Gain/Loss 와 붙는다.

## 🔴 가져오면 안 되는 것 — 이쪽이 더 중요하다

### ① 풍하 VMG 를 음수로 — `-16.1 kts, -304.8%`
부호 규약이 깨졌고, **0을 넘나드는 값에 퍼센트를 붙이면 의미가 없다.**
−304.8% 는 숫자가 아니라 노이즈다.
→ **우리는 이미 풍상·풍하 VMG 를 둘 다 양수로 저장한다.** 우리가 앞서 있다.

### ② Avg Heel 이 네 탭 전부 `+0%`
기준선이 없는데 **"+0%" 를 진짜 비교인 것처럼 찍는다.** 아무것도 안
보여주는 것보다 나쁘다 — 사용자는 "안 변했구나" 로 읽는다.
→ 델타를 넣을 때 **기준선이 없으면 칸을 비운다.**

### ③ 지표 방향을 모르는 델타%
풍상 TWA 44.8° 에 −30.6%. 풍상 TWA 는 **작을수록 좋으니 개선**인데 색이
회색이다. 풍하 TWA 는 +32.5% — 이건 좋은 건가?
→ **우리는 이미 풀었다** (`statsMetricDirection`: 풍상 TWA=`low`,
풍하 TWA 는 최적각이 140~150°라 `neutral`). 델타는 이 판정을 반드시 통과.

### ④ 기준선을 안 밝힘
"+31.3%" 가 무엇 대비인지 어디에도 없다. 본인 이력? 전체 사용자? 같은 조건?

### ⑤ TOP 20% 로 좁혀도 박스가 거의 안 움직인다
Port SOG: ALL 17.8 → TOP50 17.9 → TOP20 18.2 kt. **전 구간 0.4kt.**
→ 이건 §409 에서 우리가 이미 발견한 것과 **같은 현상**이다 —
상위 X% 앵커가 구조적으로 둔감하다. 그 필터를 넣되
**"좁혀도 거의 안 변한다"는 사실 자체를 말해 줘야** 한다.

## 2차 (화면 11~25) — 새로 나온 것

### ⑩ ⭐⭐ **Tack Bias** — 이름 붙은 P/S 비대칭 지표
`Port 18.5 · Diff −4.3% · Stbd 17.7` + 반원 게이지.
지표 선택: `Entry SOG | Min SOG | Exit SOG | Entry VMG …`

**§420·§421 이 통째로 이 얘기였는데 우리는 이름 없는 표 두 칸으로 준다.**
이름을 붙이고 **Diff 한 숫자로 요약**하면 시즌 추이로 추적할 수 있는
지표가 된다. 지금 우리 값으로는 "포트가 좀 빠르네" 에서 끝난다.

ℹ️ Diff 를 **초록/빨강이 아니라 파랑**으로 칠한 게 옳다 — 어느 택이 빠른
게 좋고 나쁨이 아니다. 우리 `statsMetricDirection` 의 `neutral` 과 같은 판단.

### ⑪ ⭐⭐ **Tracks** — 회전 **궤적**을 공통 원점에 겹치기
회전마다의 실제 경로를 로컬 XY(m)로 정규화해 전부 겹쳐 그린다.
택은 빨강/초록, 굵은 선이 중앙 궤적.

**우리에게 전혀 없는 것이다.** §497 이 "속도 대 시간" 을 겹쳤다면 이건
**"공간 궤적"** 을 겹친다. 회전이 얼마나 넓게 도는지, 미끄러지는지,
포트와 스타보드의 **모양**이 다른지가 그림 하나로 보인다.
§456 Gain/Loss(회전 손실)가 "얼마나 잃었나" 라면 이건 "왜 잃었나" 다.

### ⑫ ⭐ 회전 검출 **임계값을 사용자가 조절**
`Minimum Min SOG · Minimum Maneuver Angle · Maximum Maneuver Angle` 슬라이더.
우리 검출은 고정이다. **"무엇을 택으로 칠 것인가" 가 판단이라는 걸
인정하는 UI** 라서 정직하다 — 임계를 바꾸면 개수가 바뀌는 걸 사용자가 본다.

### ⑬ ⭐ 풍향 확인 UI — 위성지도 + **바람 화살표 오버레이** + 회전 슬라이더
`Confirm the General Wind Direction`. 지도 전체에 바람 화살표를 깔고
트랙과 같이 보여 주면서 슬라이더로 돌린다.
우리는 **숫자 입력 + 재추정** 뿐이다(§428 이 이 확인 UX 얘기였다).
**트랙과 대조해 눈으로 판정**하게 하는 게 숫자보다 낫다.

### ⑭ 외부 데이터 병합 — `Wind Sensor / Cyclops Load / Sailemetry Sail Shape`
🔴 **Cyclops = 리깅 로드셀이다.** 저쪽은 이미 하중 데이터를 병합한다 —
**SailTechFORCE 와 정확히 같은 범주**이고, 데이터 모델 선례가 있다는 뜻.
그리고 **Wind Sensor Data** 는 D1·D4 를 막고 있는 바로 그 실측 풍속이다.
우리는 §430 다중 파일 융합이 이미 있으니 **채널만 늘리면 된다.**

### ⑮ `Activity Type: Training | Racing` + `Select Focus`
Focus 태그: General / Boat Speed / Starting / Maneuvers / Strategy.
훈련이냐 레이스냐에 따라 봐야 할 지표가 다르다.
→ 세일테코 §3.4 의 TRAINING / RACE-LEGAL 모드 분리와 같은 방향.

### ⑯ 개별 회전 차트마다 **대시선 = 세션 중앙값**
회전 하나를 볼 때 모든 차트에 점선으로 "내 평소" 가 깔린다.
§497 을 **회전 단위로** 적용한 것. 값싸고 효과 크다.

### ⑰ 5등급 풍속 — `Very Light / Light / Medium / Strong / Very Strong`
세일테코 바람 5등급과 등급 수가 같다. ⑧ 의 구체형.

## 🔴 2차에서 가져오면 안 되는 것

### ⑥ 회전 시각 0 을 "head to wind" 로 정의
안내문: *"Time 0 is when the boat is head to wind."*
**자이브는 바람을 향해 돌지 않는다.** 같은 정의를 자이브에도 쓰면
기준점이 무의미해진다.
→ **우리는 apex(최저속·최대 회전율)를 쓴다.** 택·자이브 양쪽에 성립한다.
우리가 옳다.

### ⑦ `Show Trendlines` 가 기본 꺼짐
개별 선이 다 겹쳐서 안 보이는 상태가 기본이고, 제일 쓸모 있는 중앙선을
사용자가 찾아서 켜야 한다. §497 에서 우리는 반대로 갔다(밴드가 기본).
